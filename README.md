# Sub-T Training Planner

5 km タイム、COROS 閾値ペース、または手動指定から、サブスレッショルド練習の目安と週間・長期プランを見る日本語の静的 Web アプリです。HTML、CSS、Vanilla JavaScript の ES Modules で動作します。入力と選択した計算方式はブラウザの localStorage に保存されます。初期選択は5 kmタイム基準です。

## ローカルで開く

Node.js 22 以上を使用します。展開したフォルダで次のコマンドを実行し、ブラウザで [ローカルプレビュー](http://127.0.0.1:4173/) を開きます。

```sh
node tools/serve.mjs
```

開発サーバーの終了は Ctrl+C です。ES Modules を読み込むため、ブラウザからは HTTP 経由で開いてください。パッケージのインストールは不要です。

## ホーム画面への追加とオフライン利用

対応ブラウザから「アプリをインストール」または「ホーム画面に追加」を選びます。iPhone・iPad では、Safari の共有メニューから追加できます。インストール後はアプリ用のウィンドウで開きます。

利用するブラウザまたはホーム画面アプリで一度オンラインで開き、初回読み込みを完了してください。以降、キャッシュが利用できる間はネット接続なしで計算できます。オンラインで起動すると更新を確認します。画面上部に「新しいバージョンがあります」と表示されたら、「更新する」を押すと新版に切り替わり、一度だけ再読み込みします。

更新時に整理されるのは旧版のアプリキャッシュです。保存していた設定は同じ保存領域で引き継がれます。Safari から追加したホーム画面アプリなど、保存領域が別の場合は既存の「JSON出力」と「読み込み」で設定を移せます。[WebKit のホーム画面アプリの説明](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/#web-apps)

## GitHub Pages

フォルダの内容をリポジトリのルートに置いてください。隠しディレクトリの `.github` も含めます。リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定すると、`main` への push または Actions タブからの手動実行で公開できます。ワークフローは Node.js の計算テストに成功した後、アプリのファイルだけを Pages に送ります。公開 URL は GitHub の Pages 設定とデプロイ結果で確認できます。[GitHub Pages の公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

ブランチ公開を利用する場合は **Deploy from a branch → main → /(root)** を選択します。Jekyll を省くため空の `.nojekyll` を含めています。すべてのアプリ内アセットは相対パスです。[公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

GitHub Actions はコミットごとに Service Worker のキャッシュ番号を更新します。ブランチ公開でオフライン用のファイルを変更したときは `service-worker.js` の `CACHE_VERSION` を更新してください。

## 計算根拠と適用範囲

- 書籍 *Norwegian Singles Method: Subthreshold Running Kept Simple* の表 1.3、1.4、1.5〜2.2、2.5〜3.2、およびレース前調整の章を参照しました。画像で確認した計算用の数値を収録しています。
- 選択した方式の 5 km タイムを表 1.4（15:00〜30:00）に当てはめ、隣接点を秒単位で線形補間します。手動指定では3・6・10分反復の入力値を使います。
- COROS 閾値ペース基準は、閾値ペースを一定時間維持できると仮定し、Riegel モデルで5 kmタイムを推定します。初期値は60分と指数1.06です。詳細設定の持続時間と指数で調整できます。この換算は本書およびCOROS公式の指定式ではありません。レース予測タイムを使う場合は、5 kmタイム基準を選択して入力します。
- 週間プランはアプリによる再計算です。日数や1日あたりの上限のため割り当てられない時間は画面に表示します。週間時間の未入力時はサンプルの前提として5時間を使用します。
- 標準の4週維持、3週ごとに15分追加、増分の Sub-T 20%、10%超の増加警告はアプリのルールです。実際の Sub-T は反復単位です。フルのロングラン上限に使う予想完走時間は任意入力です。
- 書籍の週例は掲載時間で表示し、5・11・12分反復や朝夕2回の記載も保持します。配布物には書籍のOCR全文と画像は含まれていません。

## Easy Run Guide と COROS Pace Alert

Easy Run Guide は、選択した方式の5 kmタイムを表 2.3（15:20〜30:00）で線形補間し、速い側の上限目安を表示します。指定した最大心拍数の70%は、書籍に沿って平均心拍の上限目安として表示します。

COROS Pace Alert は表示中の Sub-T ペースから設定用の境界を秒単位で計算します。初期の許容幅は速い側5秒/km、遅い側10秒/kmです。この2値はアプリの設定で、0〜60秒/kmの範囲で調整してブラウザに保存できます。閾値心拍数を設定すると、最初と最後の反復のガードレールも表示します。

## クロストレーニング

実施曜日、1回の時間、強度を登録すると、毎週の固定予定に追加されます。その他のトレーニングは1日に1回です。週間実施回数を入力する場合は選択した曜日数とそろえてください。空欄の場合は曜日数から自動で数えます。

各種目の「計画に含める」を外すと、予定、時間集計、競合判定から一時的に除外できます。もう一度チェックすると、保存した入力値で予定を復元します。

Cross Training 章の表 3.5・3.6 は、サイクリングとランニングの両方を参考表に表示します。Week A・B の適用で追加されるのはサイクリングの行です。FTPを入力すると、参考表と予定にワット範囲が表示されます。書籍のサイクリングのインターバルは、日程確認上の高強度として数えます。

週間プランとCSVではランニング、サイクリング、その他、全運動時間、高強度クロストレーニングの回数を個別に集計します。ランニングのSub-T時間や前週比はランニングだけで算出します。同日・連続日の警告から Sub-T の回数変更を明示的に選べます。設定はこのブラウザとJSONに保存できます。
